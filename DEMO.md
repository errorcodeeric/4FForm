# Demo runbook

A five-minute walkthrough of both workflows. Written so a presenter who didn't build this can
run it cold.

## Before you start

- **Local**: `npm install && npm run dev`, open `http://localhost:3000`. Set
  `ANTHROPIC_API_KEY`/`ANTHROPIC_MODEL` in `.env.local` to demo the AI-assisted paths (resume
  import, LinkedIn import, HR extraction) — without a key, those steps return a clear "not
  configured" message and you should use the **fallback** noted at each step instead.
- **Deployed**: use the Vercel preview/production URL (see `README.md` § Deployment). The same
  fallback applies if the environment variables aren't set there either.
- Every fixture referenced below is synthetic — no real personal data anywhere in this repo.

## Part 1 — Candidate (≈3 minutes)

1. Open the app, click **Candidate**.
2. **Resume import.** Click "Import from resume", upload
   `src/lib/import/fixtures/synthetic-resume.pdf`.
   - Expected: a summary appears ("Filled in N fields from your resume") and fields like Full
     name, Email, Education, and Employment are pre-filled. Sensitive fields (NRIC, salary,
     signature) stay blank — the app never infers those from a resume.
   - **Fallback (no API key):** skip the import; instead fill in Full name, NRIC, Email, and
     Citizenship by hand to show the same fields exist and are freely editable.
3. **Missing-field review.** Scroll to the **Review** section near the bottom. Point out the
   ready/needs-confirmation/missing counts, and that "The final PDF is blocked until…" lists
   the specific missing items (e.g. Position applied for, Declaration accepted).
4. Fill in the remaining required fields quickly: Position applied for, Address, Mobile,
   Citizenship, Legal rights to work, the six Yes/No questions (any answer works), Expected
   Salary, Termination Notice. Check **Declaration accepted**, fill in a **Date**, and type a
   name into **Signature of applicant (typed, POC only)**.
   - Expected: the Review section now says "The final PDF is ready to export."
5. **Original-layout PDF.** Click **Download completed PDF**.
   - Expected: a PDF downloads with the values overlaid onto the real 4FINGERS letterhead form
     — same branding and layout as the source document, not a recreated one.
6. **Structured export.** Click **Download CSV** and **Download XLSX**.
   - Expected: CSV opens with one row of data; XLSX has a **Candidate Data** sheet and a
     **Field Dictionary** sheet.

## Part 2 — HR (≈2 minutes)

1. Go back to the landing page, click **HR**.
2. Upload `src/lib/hr/fixtures/synthetic-completed-form.pdf` (a synthetic *completed* copy of
   the same template, generated by this app's own PDF-overlay step).
   - Expected: a card appears showing the file name, "Extracted", a missing/low-confidence
     count, and two clearly separated sections — **Candidate fields** and **For official use
     only** (the latter visually distinct, e.g. a shaded background).
   - **Fallback (no API key):** the card will show "Failed" with a "not configured" message —
     explain that this is the same extraction pipeline as candidate resume import, gated by
     the same environment variable, and point to the code (`src/lib/hr/extractForm.ts`) and
     its test suite (`extractForm.test.ts`) as evidence it works against a mocked response.
3. If extraction succeeded, edit one field inline (e.g. correct a name) to show the review
   step isn't a read-only preview.
4. Click **Export reviewed CSV** (or XLSX).
   - Expected: a file downloads with one row for the reviewed record.

## 60-second architecture explanation

- **One canonical schema** (`src/lib/schema/`) drives the form UI, AI extraction, PDF overlay,
  and CSV/XLSX export — every field is defined once, by ID, so nothing can drift between them.
- **Next.js on Vercel, no database.** Candidate data lives in browser memory and request memory
  only; nothing is written to disk anywhere in this app. Files may transit the Anthropic API
  during AI-assisted extraction — that's disclosed in the UI, not hidden.
- **The PDF is never recreated** — `pdf-lib` loads the real, immutable source file and draws
  values onto it at calibrated coordinates, so the output keeps the original branding exactly.
- **AI extraction always requires human review.** Every extracted field carries a
  high/medium/low confidence flag; low-confidence values are flagged for confirmation, and HR
  mode's `templateMatch` check rejects an unrelated document with a clear message instead of
  fabricating a record.

## Deliberate deferrals (if asked "why doesn't it do X?")

Straight from the spreadsheet's Scope & Decisions tab — worth having ready:

- **No database, no accounts/auth** — this is a single-user interview POC with a transient-data
  requirement, not a saved-submission product yet.
- **One fixed template only** — a generic PDF form builder is out of scope until a second,
  genuinely different form is funded.
- **No LinkedIn API/scraping** — only user-supplied files or pasted text; the official LinkedIn
  API is restricted and scraping carries policy/fragility/credential risk.
- **No edited-PDF generation from HR mode** — HR mode extracts and reviews; only candidate mode
  produces the overlaid PDF.
- **Typed signature only (no drawn signature, no e-signature compliance)** — a POC affordance,
  not a legally binding signature; the schema already supports a future `kind: "drawn"` without
  a breaking change.
- **No perfect handwriting/OCR accuracy claim** — explicitly best-effort; uncertain fields are
  flagged for human review rather than silently trusted.

## Known limitations to mention if asked

- No real `ANTHROPIC_API_KEY` was available while building this, so the live AI extraction
  paths (resume, LinkedIn, HR) are verified via fixture-based tests against a mocked Anthropic
  client, not a live model call — see `docs/SESSION_LOG.md` (S04, S09) for the exact test
  evidence, and run one for real once a key is configured.
- PDF overlay coordinate calibration (S07) is a good-faith pass, not pixel-perfect — a few
  fields have minor cosmetic crowding against their printed labels; documented with the exact
  list in `docs/FIELD_MAP.md`.
- Deployment (S13) and its live smoke test (T25 in the Acceptance Tests tab) were handed off to
  be run with real credentials — see `README.md` § Deployment.
